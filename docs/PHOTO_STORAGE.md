# Фотографии блюд

В кабинете поставщика → «Пул блюд» → добавить или изменить блюдо:

- «Выбрать фото» открывает выбор изображения из галереи или файлов.
- «Сфотографировать» использует мобильный file input с `capture="environment"`: на поддерживаемом телефоне открывается камера. На компьютере браузер может открыть выбор файла.
- После выбора из галереи или камеры открывается кадрирование. Фото можно двигать пальцем, приближать двумя пальцами или ползунком, поворачивать на 90°; форматы — 4:3, квадрат и исходные пропорции.
- «Обрезать и загрузить» отправляет только выбранный фрагмент. До подтверждения фото остаётся в браузере; отмена не создаёт загрузку и сохраняет прежнее изображение.
- После загрузки показывается превью. Сохраните карточку блюда, чтобы применить фото.

Браузер обрезает изображение локально, затем уменьшает выбранный фрагмент до 1600 px по длинной стороне и сжимает до 900 КиБ, чтобы загрузка работала за обычным reverse proxy с лимитом 1 МиБ. Исходный файл — до 25 МиБ и 40 мегапикселей. Сервер независимо проверяет реальные байты, ограничивает размер 10 МиБ / 40 мегапикселей, поворачивает по EXIF и перекодирует в WebP без исходных метаданных, включая геометки. JPG/PNG/WebP поддерживаются; HEIC из галереи подходит, если браузер умеет его декодировать. Для неподдерживаемого формата интерфейс предлагает выбрать JPG/PNG/WebP.

## Хранение и доступ

На сервере используется существующий `libnode-test-minio` через опубликованный S3-порт `9100`. Для lunch-together создан отдельный приватный бакет с квотой 2 GiB и отдельная учётная запись. Имя бакета и ключи хранятся только в серверном `.env`; root-ключи MinIO в приложение не передаются. Существующие бакеты, пользователи и контейнер MinIO не меняются.

Приложению нужны только `s3:GetObject`, `s3:PutObject`, `s3:DeleteObject` для `arn:aws:s3:::BUCKET/dishes/*`. Права на список бакетов, администрирование и чужие данные не нужны. Пример IAM policy:

```json
{"Version":"2012-10-17","Statement":[{"Effect":"Allow","Action":["s3:GetObject","s3:PutObject","s3:DeleteObject"],"Resource":["arn:aws:s3:::BUCKET/dishes/*"]}]}
```

Переменные: `S3_ENDPOINT`, `S3_BUCKET`, `S3_ACCESS_KEY`, `S3_SECRET_KEY`, `S3_REGION` (по умолчанию `us-east-1`). В Docker на этом сервере endpoint — `http://host.docker.internal:9100`; Compose добавляет адрес host gateway. Эти переменные не относятся к Vite и не попадают в клиентскую сборку. Без конфигурации сайт работает с фото-примерами, а загрузка возвращает понятную ошибку 503.

Сами изображения лежат в MinIO, PostgreSQL хранит владельца, ключ объекта, размеры и ссылку `/media/UUID.webp`. Приложение отдаёт фото через собственный домен с immutable cache; публичная политика бакета, отдельный домен и CORS не нужны. Фото блюда публично доступно по его случайному URL. Загружать и привязывать новое фото может только поставщик-владелец. Фото не перезаписываются: изменения каталога не ломают сохранённые меню и старые заказы. Архивирование блюда сохраняет его фото. Неиспользованные загрузки автоматически не удаляются; место ограничено квотой бакета.

Резервная копия PostgreSQL содержит ссылки, но не байты изображений. В резервирование нужно включать отдельный фото-бакет и `.env` вместе с базой. Существующий backup основного бакета libnode этот новый бакет не охватывает. Для переноса используйте S3 API; работающий каталог данных MinIO напрямую не копируйте.

## Локальная разработка и проверки

`compose.storage-dev.yml` поднимает отдельный MinIO на `127.0.0.1:55438` с томом. Используйте только приведённые в нём локальные credentials, отдельный бакет `lunch-dev-photos` и соответствующий localhost endpoint. Бакет создаётся заранее через S3/MinIO CLI; приложение не получает административных прав. Dev proxy обслуживает и `/api`, и `/media`.

Изолированные тесты используют `compose.test.yml`: PostgreSQL на 55436, MinIO на 55437, tmpfs и тестовые credentials. Тестовый MinIO собирается из закреплённой версии официальных исходников, поскольку старые бинарные образы могут быть недоступны. Тесты не подключаются к рабочему серверу.

```sh
docker compose -f compose.test.yml up -d --wait
TEST_DATABASE_URL=postgresql://lunch_test:disposable_test_password@127.0.0.1:55436/lunch_test TEST_S3_ENDPOINT=http://127.0.0.1:55437 npm test
docker compose -f compose.test.yml down
```

Проверяются загрузка через настоящий S3, поворот/уменьшение, удаление метаданных, отказ для SVG/повреждённых/слишком больших файлов, Origin, авторизация, принадлежность фото и сохранение снимка меню. Физическую камеру и жест двумя пальцами проверяют на самом телефоне. Браузерная проверка на мобильной ширине подтверждает оба file input, перемещение кадра, масштаб, поворот, форматы, отмену без загрузки и реальные размеры сохранённого WebP. Геометрия поворота, границы кадра и ограничение размера дополнительно покрыты `server/test/photo-crop.test.mjs`.
